# ボール台帳

建売・注文住宅の案件ごとに、**いま誰がボールを持っていて、何日止まっているか**を
関係者全員がリアルタイムで共有するための1枚ページ。

公開先: https://claude.ai/code/artifact/3a8bf781-2fb8-4deb-a895-bd322dbf8b59

## 誰が使うか

初期の名簿（画面の「名簿」からいつでも追加・変更できる）:

| 名前 | 得意分野 |
|---|---|
| 専務 | 決裁・全体判断 |
| 酒井 | （未設定） |
| 拓也 | 設計 |
| 山口 | 工事 |
| 渡邉 | 土地決済・契約手続き・物件売却 |

得意分野は、ボールを渡すときと質問するときに名前の下に出る。誰に振るべきかが選ぶ画面で分かる。

## 何が見えるか

- **ボールの持ち主** — 案件ごとに「誰が」「何を」抱えているか。担当者別の件数も上部に集計
- **停滞日数** — 最後に動いてから何日経ったか。3日で注意（琥珀）、7日または期限超過で警告（赤）
- **やりとりの記録** — 誰がいつ何を言って誰に渡したかが全部残る。言った言わないが消える
- **未回答の質問** — 誰かの質問に答えていない案件は、全員の一覧の最上部に上がり、答えるまで下がらない
- **工程** — 用地・仕入 → 企画・設計 → 確認申請 → 契約 → 着工 → 上棟 → 内装・設備 → 完了検査 → 引渡・決済

自分に関係するものは、画面を開いた瞬間に上部に固定表示される。

1. **あなたの質問に返答がありました** — 自分が出した質問への答え（開くと消える）
2. **あなたへの質問** — 自分あての未回答（何日待たせているかつき）
3. **あなたが持っているボール** — 停滞の重い順

## 使い方

1. 右上の「あなた」で自分の名前を選ぶ（端末に記憶され、以後は聞かれない）
2. 下の「＋ 案件を追加」で物件を登録する
3. 自分が持っているボールは、開いた瞬間に最上部に固定表示される
4. 上部の担当者カードを押すと、その人のボールだけに絞り込まれる。
   「貼り付ける文面をつくる」で LINE / Chatwork にそのまま貼れる文章ができる
5. カードを押すと操作が開く
   - **ボールを渡す** — 相手と依頼内容を書いて引き渡す。停滞日数がリセットされる
   - **進捗を書く** — ボールは持ったまま、動きがあったことを記録する
   - **催促する** — 停滞日数はリセットせずに催促を記録する（「頼んだのに動いていない」が残る）
   - **質問する** — 相手を選んで聞く。答えが返るまで全員の最上部に出続ける
   - **返答する** — 質問バンドの右にあるボタンから。答えると質問者の画面に返る
   - **工程を進める** / **編集** / **完了にする**

全員の画面が自動で同期する。リロードは不要。

## Chatwork との連携について

現状は手動。担当者を選んで「貼り付ける文面をつくる」で文章を生成し、Chatwork に貼る。
ボールの一覧に加えて、その人あての未回答の質問も入る。台帳のURLは初回に一度入力すれば
`meta/config` に保存され、以後は文面の末尾に自動で付く。

### 自動通知の経路（未実装・実現可能）

このページ自身から外部APIを叩くことはできない（アーティファクトのCSPが外部への
fetch を遮断している）。また Zapier からこのボードのデータを読むこともできない。

正しい経路は、定期実行させたセッションがボードを読んで判定し、通知を投げる形:

    毎朝の定期実行 → ボードのDBを読む → 停滞・未回答を判定 → Chatwork / SMS / 電話

ボードのDBが外部から読めることは確認済み（アーティファクトの read_db）。
定期実行は create_trigger（Routine）で組める。

必要なもの:

- Chatwork の APIトークン と 投稿先ルームID（無料）
- SMS・電話まで出すなら Twilio のアカウントと発信用番号（有料、Zapier連携あり）

なお LINE への自動投稿は当面できない。Zapier に LINE の連携アプリが無く、
LINE Notify も 2025年3月31日に終了しているため、LINE公式アカウント（Messaging API）を
自前で構築するしかない。

## 共有の条件

このページは `db` 機能（共有データベース）を使っているため、**閲覧・書き込みできるのは
オーナーと同じ組織にサインインしているメンバーだけ**で、一般公開はできない。
社外や、claude.ai のアカウントを持たない人には見えない。

## 技術メモ

- 単一の `index.html`。外部スクリプトなし、フォントのみ Google Fonts
- データ構造
  - `cases/<id>` — `{title, kind, phase, holder, ask, due, status, movedAt, updatedAt, createdAt, createdBy, pending[], lastReply}`
    - `pending` は未回答の質問の配列 `{id, at, by, to, text}`（最大6件）。カードに出す判定用
    - `lastReply` は直近の返答 `{at, by, to, text, q}`。質問者の画面に返すため
    - 配列は last-writer-wins のため、同じ案件に同時刻で質問すると表示が1件落ちることがある。
      ただしログには必ず残るので内容は失われない
  - `cases/<id>/log/<id>` — `{at, by, kind, text, to}`（1操作1ドキュメント。同時書き込みでも取りこぼさない）
  - `meta/members` — `{list: [...], roles: {名前: 得意分野}}`
  - `meta/config` — `{shareUrl}`
- 1アーティファクトあたり最大5,000ドキュメント。上限に達したら古い案件を削除する
- 更新は同じファイルパスで再公開すればURLは変わらない
- ログの `<li>` のクラスは `k-<種別>` と接頭辞を付ける。`ask` / `phase` は
  カード側のクラスと衝突するため

## 動作確認

`scratchpad/run.js` に Playwright のシナリオテストがある（`window.claude.use("db")` を
インメモリ実装に差し替えて実行）。案件登録 → 質問 → 名前を切り替えて返答 →
質問者の画面に返る、までを通しで確認する。
